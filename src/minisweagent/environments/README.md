# Environments

- `local.py` executes each fenced action in a fresh Python process (`sys.executable -u -c`). Files persist; variables, imports, and changes to cwd/environment do not. `environment.language: bash` selects Bash instead. `environment.interpreter` optionally overrides the interpreter argument list, e.g. `["/project/.venv/bin/python", "-u", "-c"]`. The resolved interpreter and language are saved in trajectories.
- The checkout's `benchmarks/docker.py` executes benchmark commands with the Docker CLI and is not installed with the core.
- `podman.py` is an optional local sandbox: `mini --sandbox --sandbox-image IMAGE` blocks action networking. `mini --ask-network --sandbox-image IMAGE` keeps actions offline unless a script's first line is `# network: reason` and the user types `yes` in the shared multiline prompt (Ctrl-G sends). Each approval covers that script and its children only. Empty input, noninteractive input, and denials never grant access. Unmarked scripts stay offline; failed actions are never automatically replayed with networking.

`get_environment` accepts `environment_class: local` or `podman`. Podman additionally requires a preloaded `image` and accepts `network: none` (default) or `ask`. The image supplies Python (`python3`) and project dependencies. Only the selected `cwd` is mounted writable at `/workspace` (privately relabeled on SELinux hosts); the image filesystem is read-only and temporary files disappear after each action. Mini, its Python installation, trajectories and command logs must be outside that workspace, so generated code cannot modify the controller or replace host-side logs. Use the installed `mini` command or `python -P -m minisweagent` to keep the workspace off the controller's import path. Host environment variables, home, proxy settings, engine sockets and default secret mounts are not forwarded. Only explicit `environment.env` values are forwarded; files already in the workspace remain accessible. Sandbox failures stop execution; there is no local fallback. Podman seccomp support is required: only IPv4/IPv6 socket creation is allowed, preventing mounted Unix sockets or other socket families from bypassing network isolation. This also prevents Unix-socket-based tests and IPC. Approved scripts get general IP networking; approval is not a domain allowlist. The CLI's configured model API remains outside the action sandbox, and task/observation text is still sent to that model.

Language details live in `targets.py`; prompts, parsing, and human command entry use that same target. `mini setup --language python` tests the interpreter and model response before saving; Python is the default for both setup and normal runs. Existing custom Bash prompts/parser overrides require `environment.language: bash` (or `--language bash`).
